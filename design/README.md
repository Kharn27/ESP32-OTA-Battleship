## Fondations, statut et limites

- **G01 — identité maritime : VALIDÉ PO** au stade de direction artistique, voir [contrat graphique](fondations/CONTRAT_GRAPHIQUE.md), [Issue #16](https://github.com/Kharn27/ESP32-OTA-Battleship/issues/16), [PR #19](https://github.com/Kharn27/ESP32-OTA-Battleship/pull/19). **La recomposition ATTAQUE G01 n'est PAS une maquette ATTAQUE approuvée.**
- **OBSOLÈTES / REFUSÉES :** les anciennes versions de combat G01 initiale, V2, V2.1, comparatifs et recomposition expérimentale ont été retirées de l'arbre actif. Elles restent consultables dans [Git avant nettoyage](https://github.com/Kharn27/ESP32-OTA-Battleship/tree/dab6e891657078b65229b4f2de33edd995309498/design/issue-16-direction-lot1), [PR #19](https://github.com/Kharn27/ESP32-OTA-Battleship/pull/19) et [décisions PO de #16](https://github.com/Kharn27/ESP32-OTA-Battleship/issues/16). **Ne pas les traiter comme des références courantes.**
- **La géométrie 18×18 / plateau 180×180 de G07 R1/G08** est un **invariant de cadrage technique**, pas une validation du style G07 R1. La charte de combat R2 sera définie par G04-R2 puis harmonisée sur G05-R2/G07-R2 ; aucun thème R1 rejeté ne doit être réutilisé par défaut.
- **Aucune entrée n'est `ON_DEVICE_VERIFIED`** : image PC 320×240 ≠ rendu TFT/stylet ≠ pack d'assets embarqué. Les mesures Flash/RAM statiques de CI firmware ne valident pas les futurs sprites. Aucun format de production, hitbox, licence d'intégration ou workflow artistique permanent n'est ajouté par ce rangement.
- Chaque future PR graphique doit **mettre à jour cet index en remplaçant la référence courante**, conserver ses variantes passées dans Git/PR (pas dans un sous-dossier d'archives) et versionner des sources/export reproductibles ; Pilotage seul fusionne. L'Issue de travail est une métadonnée, **pas** le nom permanent du répertoire.
